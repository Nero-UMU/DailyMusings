## 复现构建

Android APK（需要 `maui-android` 工作负载与 Android SDK；必须是 Release，Debug 版依赖 Fast Deployment，单独安装会以「No assemblies found」启动失败）：

```bash
dotnet build src/DailyMusings.Client -f net10.0-android -c Release -t:SignAndroidPackage
# 产物：src/DailyMusings.Client/bin/Release/net10.0-android/dev.dailymusings.client-Signed.apk
```

Windows 安装包（MSIX，需要 `maui-windows` 工作负载）。**必须显式打开签名**：打包目标只在给了证书*文件*（`PackageCertificateKeyFile`）时才自动签，只给指纹是不够的，`SignAppxPackageExeFullPath` 也要指到 `signtool.exe`（本仓库用的是 Visual Studio 共享包里的 Windows SDK 构建工具）：

```powershell
dotnet publish src\DailyMusings.Client -f net10.0-windows10.0.19041.0 -c Release `
  -p:WindowsPackageType=MSIX -p:GenerateAppxPackageOnBuild=true `
  -p:AppxPackageSigningEnabled=true `
  -p:PackageCertificateThumbprint=C7FD833B2A89492BC613F91B1556E1A32334D4DE `
  -p:SignAppxPackageExeFullPath="C:\Program Files (x86)\Microsoft Visual Studio\Shared\NuGetPackages\microsoft.windows.sdk.buildtools\10.0.26100.1742\bin\10.0.26100.0\x64\signtool.exe"
# 产物：src\DailyMusings.Client\bin\Release\net10.0-windows10.0.19041.0\win-x64\AppPackages\
#        DailyMusings.Client_1.0.0.0_Test\DailyMusings.Client_1.0.0.0_x64.msix
```

Windows 免安装包（自包含，解压即用；含 .NET 与 Windows App SDK 运行时）：

```powershell
dotnet publish src\DailyMusings.Client -f net10.0-windows10.0.19041.0 -c Release `
  -p:WindowsPackageType=None -p:SelfContained=true -p:UseMonoRuntime=false `
  -p:WindowsAppSDKSelfContained=true -p:RuntimeIdentifier=win-x64 -o artifacts\windows
```

`UseMonoRuntime=false` 不是可选项：`SelfContained=true` 会沿着 MAUI 的默认值去还原 `Microsoft.NETCore.App.Runtime.Mono.win-x64`，而该运行时包并不存在，还原会直接失败。

## 签名

MSIX 用自签名证书签名，**没有**商用时间戳，因此：

- 证书 `CN=DailyMusings`，指纹 `C7FD833B2A89492BC613F91B1556E1A32334D4DE`，有效期至 2027-09-16，公钥已导出为 `DailyMusings-client.cer`。
- 签名是否真的进了包，`Get-AuthenticodeSignature` 单独看不出来（它不懂 AppX 容器）。两个可靠办法：包里存在 `AppxSignature.p7x`，以及 `signtool verify /pa <msix>` 报 `Successfully verified`。
- **安装前必须把证书导进「本机」的两个存储**，普通用户身份不够——`AppXSvc` 以 SYSTEM 运行，只认本机存储：

  ```powershell
  # 需要管理员 PowerShell（一次 UAC）
  certutil -addstore -f TrustedPeople .\DailyMusings-client.cer
  certutil -addstore -f Root        .\DailyMusings-client.cer
  Add-AppxPackage .\DailyMusings.Client_1.0.0.0_x64.msix
  ```

  只导入当前用户的存储（`Cert:\CurrentUser\...`）会以 `0x800B0109`「根证书不受信任」被拒；把证书导进「受信任人」之后还要求根证书可信，所以自签名证书两处都要放。

- 自签名证书在别的机器上不被信任，这是预期行为，不是包的问题。Android APK 同理：它是自签名的 debug 式签名包（未上架），安装时系统会提示「未知来源」，需要手动允许。

## 打包形态验收（2026-09-17）

按上面的命令构建并签名后，在 Windows（WinUI 10.0.26200.9457，x64）上完成了一次完整的打包形态验收，全部按人手操作用 UI Automation 驱动：

1. `certutil` 把证书导入本机「受信任人」与「根」，`Add-AppxPackage` 安装成功，`Get-AppxPackage` 显示 `dev.dailymusings.client_1.0.0.0_x64__znmbb1qq8g0wc`、`Status: Ok`。
2. 从开始菜单启动（`shell:AppsFolder\dev.dailymusings.client_znmbb1qq8g0wc!App`），进程路径为 `C:\Program Files\WindowsApps\dev.dailymusings.client_1.0.0.0_x64__znmbb1qq8g0wc\DailyMusings.Client.exe`——确实跑在包标识下，不是解压出来的绿色版。
3. 五个页面都在：今日 / 草稿 / 日历 / 主题 / 设置。
4. 设置页填 HTTP 地址 → 弹出明文风险确认（确认后横幅常驻）→ 测试连接「服务器有响应。」→ 用管理页签发的一次性配对码配对成功，服务端记录到的设备名是真实平台（不是写死的 android）。
5. 配对成功后立即读到实例信息：通知偏好（收件地址、已开启的事件、以及「设备令牌没有修改收件地址的权限」）与实例上的模型名（语音转写：stub-whisper / 文章生成：stub-chat / 语义检索：stub-embed）。
6. 今日页列出服务端的 9 条输入（含转写、修订稿、主题归属与「草稿需要重新生成」提示），**用 PC 麦克风录了 14 秒**并停止保存 →「已上传到服务器。」「已上传 1 条。」→ 列表变成 10 条且新条目显示「已转写」。
7. 核对产物的同一性：安装目录里的 `DailyMusings.Client.dll` 与本 MSIX 包内同名文件的 SHA-256 逐字节一致（`d0d5f3ca…`），因此上面跑的就是这里给出校验值的那份产物。

验证结束后包**留在了那台机器上**（想移除就 `Remove-AppxPackage dev.dailymusings.client_1.0.0.0_x64__znmbb1qq8g0wc`）。为了安装而写进本机（以及当时试过的当前用户）证书存储的那几个 `CN=DailyMusings` 条目是验证过程的副作用，与产品无关，可以照常删除。

## 客户端安装说明

- **Android**：Android 8.0（API 26）及以上。安装 APK 后首次进入设置页填入服务端地址，再用管理页签发的十分钟一次性配对码完成配对。录音权限在第一次按下录音按钮时申请。
- **Windows**：Windows 10 1809（10.0.17763）及以上，x64。两种装法二选一：装 MSIX（开始菜单里像普通应用一样，需先按上面「签名」一节把证书导入本机存储），或解压 `DailyMusings-client-1.0.0-win-x64.zip` 直接运行 `DailyMusings.Client.exe`。首次进入设置页填服务端地址并配对。录音需要「麦克风」权限，Windows 会在第一次录音时询问。

操作步骤见 [`使用手册.md`](使用手册.md)。
