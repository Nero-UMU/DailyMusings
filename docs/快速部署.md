# 每日随想 · 快速部署

目标：**一份 compose 文件 + 一个 APK**。不克隆源码、不装 SDK、不编译。

需要准备的东西只有两样：

| | 要求 |
| --- | --- |
| 服务端 | 一台装了 Docker 与 Docker Compose 的机器（Linux / NAS / Windows 或 macOS 上的 Docker Desktop 都行）；架构支持 amd64 与 arm64 |
| 手机 | Android 8.0（API 26）及以上 |

镜像发布在 `ghcr.io/nero-umu/dailymusings`（`linux/amd64` 与 `linux/arm64`，公开包，不需要登录即可拉取）。

---

## 1. 拿到这份文件

它就是这么长，**一个字都不用改**：

```yaml
name: dailymusings

services:
  app:
    image: ${DM_IMAGE:-ghcr.io/nero-umu/dailymusings:latest}
    container_name: dailymusings
    restart: unless-stopped
    environment:
      DM_LOCK_LISTENING_PORT: "${DM_LOCK_LISTENING_PORT:-1}"
      TZ: "${DM_TZ:-Asia/Shanghai}"
      Admin__InitialPassword: "${DM_ADMIN_PASSWORD:-}"
    ports:
      - "${DM_PORT:-18321}:18321"
    volumes:
      - ${DM_DATA_DIR:-./data}:/var/lib/dailymusings
      - ${DM_CONFIG_DIR:-./config}:/var/lib/dailymusings-config
```

保存成 `docker-compose.yaml` 就行。仓库根的 [`compose.yaml`](../compose.yaml) 与它逐字相同（只有一行说明性注释），也可以一条命令取回：

> **两个目录里装什么**：`./data`（`DM_DATA_DIR`）**只放 Markdown**——后台「发布设置」里填的两个目录都以它为根：映射了 `/srv/dailymusings/data:/var/lib/dailymusings`、页面里填 `aaa/bbb/posts`，稿件就落在宿主上的 `/srv/dailymusings/data/aaa/bbb/posts`。`./config`（`DM_CONFIG_DIR`）放其余全部状态：SQLite、录音、可读导出、备份包、登录密钥环、`runtime.json`。
>
> **从 1.0.8 之前的版本升级**：布局变过一次（库与录音从数据目录搬进配置目录，稿件从 `markdown/` 底下上移一层），实例**不会自动搬**，直接升级会看到一份空实例。升级前照 [`README.md`「部署参数」](../README.md#部署参数)末尾那段命令挪一次目录即可。

```bash
mkdir dailymusings && cd dailymusings
curl -fsSLO https://raw.githubusercontent.com/Nero-UMU/DailyMusings/main/compose.yaml
```

> 镜像与文件必须能匿名取到：本仓库是公开的，镜像也是公开包。若哪天改成私有，`docker compose up -d` 会以 `unauthorized` 失败，那时先 `docker login ghcr.io` 或把包设为公开。

**所有可设置的参数都列在 [`README.md` 的「部署参数」](../README.md#部署参数) 一节**（端口、两个目录、初始密码、时区、镜像、端口锁，以及「用具名卷」的变体），这里不再重复一遍免得两边说法走样。注意那份参数表里**没有 API Key**：凭据只能登录管理页填（A.27），部署配置提供不了。

默认落在这份 compose 同级的两个目录里：**`./data`** 是 SQLite、录音、备份、导出和 `markdown/` 下的全部稿件；**`./config`** 是 `runtime.json`、登录密钥环和管理页保存的凭据。配置目录装着能签发登录 Cookie 的密钥，单独保存、不要混进普通内容备份。两个目录都不需要预先创建、也不需要 `chown`。

## 2. 起服务

```bash
docker compose up -d          # 第一次会拉镜像，约 270MB
docker compose ps             # STATUS 里出现 (healthy) 就对了
curl http://127.0.0.1:18321/api/system/health
```

记下管理员初始密码（如果指定了 `Admin__InitialPassword`，这里写的是「密码来自部署配置」，不会再显示密码）：

```bash
docker compose logs app | grep -A2 '已创建管理员账号'
```

## 3. 手机装 APK

去 [Releases](https://github.com/Nero-UMU/DailyMusings/releases) 下载最新的 `DailyMusings-client-<版本>-android.apk`，传到手机上安装。APK 是自签名包（没上架应用商店），系统会提示「未知来源」，需要手动允许。同一页给出 SHA-256，在意就核对：

```bash
sha256sum DailyMusings-client-1.0.0-android.apk
```

## 4. 登录与配对

1. 浏览器打开 `http://<这台机器的IP>:18321/`，用 `admin` + 第 2 步拿到的初始密码登录。**首次登录会强制你同时改账号名和密码**。
2. 回「状态」页的「设备配对」区点「生成配对码」：一次性、十分钟有效。
3. 手机打开「每日随想」→ 设置页填 `http://<这台机器的IP>:18321` → 点「测试连接」→ 填配对码 → 点「配对」。
4. 之后就可以用「今日随想」页录音或手写，点「上传」把内容发到服务端。

**不知道这台机器的 IP？** 在服务器上执行：

```bash
hostname -I          # 或者：ip -4 addr show | grep inet
```

取 `192.168.x.x` / `10.x.x.x` / `100.x.x.x`（Tailscale）形式的地址。手机必须能直达它：同一个局域网、连同一个 VPN，或者你把端口映射出去。**先在服务器上 `curl http://127.0.0.1:18321/api/system/health` 自证可达**，再去怀疑手机那一侧。

要真正生成文章，还需要在管理页「模型管理」里填至少一个生成模型（默认 DeepSeek）的 API Key；转写与邮件同理，都在管理页里填，保存即生效，不需要重启容器。

## 常用操作

```bash
docker compose logs -f app                     # 跟踪日志
docker compose pull && docker compose up -d    # 升级到最新版
docker compose down                            # 停止（./data 与 ./config 原样留着）
docker compose up -d                           # 再起来
```

**备份**：管理页「系统设置」里可以一键备份、导出可读包；也可以直接备份 `./config`（或 `DM_CONFIG_DIR` 指向的目录，库与录音都在那里）。`./data`（Markdown）按需单独留一份即可——它只装稿件。`./config` 必须单独保护：没有它，恢复后所有设备都要重新配对、管理员会话也会失效。

**从公网访问**：在前面放一个终止 TLS 的反向代理（Caddy / Nginx / Traefik），不要把明文端口直接暴露出去。明文 HTTP 可用，但登录页会要求你主动确认风险——**确认不会让连接变安全**，密码、设备令牌、录音和文章都可能被同一网络中的他人截获。

## 出问题先看这里

| 现象 | 原因与处理 |
| --- | --- |
| 日志里出现「无法纠正 … 的属主」 | 挂载目录的属主不对：在宿主机上 `sudo chown -R 1654:1654 <那个目录>` 再重启。Docker Desktop（Windows / macOS）上这条可以忽略 |
| 容器起来但浏览器连不上 | `docker compose port app 18321` 看映射到哪儿了；再查防火墙与云安全组 |
| 日志里没有初始密码 | 说明指定了 `Admin__InitialPassword`，或者管理员早就建好了（密码只打印一次）。忘了密码：留好备份后删掉 `./data` 与 `./config` 重来，或用备份恢复 |
| 手机「测试连接」失败 | 手机与服务器要在同一个可达网络；地址必须以 `http://` 开头并带端口；先在服务器上 `curl 127.0.0.1:18321/api/system/health` 自证 |
| 模型调用报「没有密钥」 | 管理页「模型管理」里还没填 API Key。A.27 起只能在这里填：环境变量、挂载文件、compose 都不再被读取 |
| Fedora / RHEL / CentOS 上挂载目录读不到 | SELinux：给挂载加 `:z`，如 `- ./data:/var/lib/dailymusings:z` |
| 改了管理页的「监听端口」没用 | 有意为之：容器部署下端口由部署文件独占（`DM_LOCK_LISTENING_PORT=1`，见 README 的「部署参数」）。改 `ports` 左边那个数字（或 `DM_PORT`）再 `up -d` |
| 端口被占 | `ss -ltn \| grep 18321` 看谁占着，换一个宿主机端口 |

## 我要改代码 / 从源码构建

维护者通道只有一份服务定义，覆盖文件在 `deploy/`：

```bash
docker compose -f compose.yaml -f deploy/compose.yaml up -d --build
```
