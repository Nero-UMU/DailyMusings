# 每日随想 · 快速部署

目标：**一份 compose 文件 + 一个 APK**。不克隆源码、不装 SDK、不编译。

需要准备的东西只有两样：

| | 要求 |
| --- | --- |
| 服务端 | 一台装了 Docker 与 Docker Compose 的机器（Linux / NAS / Windows 或 macOS 上的 Docker Desktop 都行）；架构支持 amd64 与 arm64 |
| 手机 | Android 8.0（API 26）及以上 |

镜像由 GitHub Actions 发布在 `ghcr.io/nero-umu/dailymusings`（`linux/amd64` 与 `linux/arm64`）。

---

## 1. 写这一份文件

在任意一个空目录里建一个 `docker-compose.yaml`，内容就是下面这些。**一句话都不用改也能起来**：

```yaml
services:
  app:
    image: ghcr.io/nero-umu/dailymusings:latest
    restart: unless-stopped
    environment:
      ASPNETCORE_ENVIRONMENT: Production
      ASPNETCORE_URLS: http://+:18321
      DAILYMUSINGS_LOCK_LISTENING_PORT: "1"
      Storage__RootPath: /var/lib/dailymusings
      Storage__SecretsPath: /run/secrets
      Storage__KeyRingPath: /var/lib/dailymusings-config/keys
      Storage__RuntimeConfigPath: /var/lib/dailymusings-config/runtime.json
      # 不想从日志里找初始密码，就把下面这行取消注释并改成自己的（至少 12 位）；不填也行。
      # Admin__InitialPassword: "换成你自己的初始密码"
    ports:
      - "18321:18321"
    volumes:
      - dm-data:/var/lib/dailymusings
      - dm-config:/var/lib/dailymusings-config
    healthcheck:
      test: ["CMD-SHELL", "curl --fail --silent --show-error http://127.0.0.1:18321/api/system/health"]
      interval: 30s
      timeout: 5s
      retries: 5
      start_period: 30s

volumes:
  dm-data:
  dm-config:
```

> 仓库根目录的 [`compose.yaml`](../compose.yaml) 就是这份文件的完整版（带注释、可选的 Secret 目录挂载、时区等）。上面那份精简版已经够用，直接复制即可；仓库可匿名访问时也可以用一条命令取完整版：
>
> ```bash
> curl -fsSLO https://raw.githubusercontent.com/Nero-UMU/DailyMusings/main/compose.yaml
> ```
>
> 同理，镜像 `ghcr.io/nero-umu/dailymusings` 必须对拉取者**可见**（公开包，或先 `docker login ghcr.io`），否则 `docker compose up -d` 会以 `unauthorized` 失败；APK 也要在能下载到的地方。

想改什么，都在上面这几行里：

| 想做的事 | 怎么改 |
| --- | --- |
| 换端口（例如 8080） | `ports` 改成 `"8080:18321"`，右边（容器内）**不要动** |
| 数据放到自己指定的目录 | 加一行 `- /srv/dm/data:/var/lib/dailymusings`，删掉 `dm-data` 那行和文件末尾的 `dm-data:`；目录不需要预先创建，也不需要 chown |
| 配置放到自己指定的目录 | 同理，把 `/srv/dm/config` 挂到 `/var/lib/dailymusings-config` |
| 固定一个版本而不是 `latest` | `image: ghcr.io/nero-umu/dailymusings:1.0.0` |
| 直接从文件给 API Key 而不是在管理页填 | 加一行 `- ./secrets:/run/secrets:ro`，把文件放进 `./secrets/`（文件名固定为 `deepseek-api-key`、`openai-api-key`、`embedding-api-key`、`smtp-password`，权限 644） |
| 容器日志换个时区 | 环境变量里加 `TZ: Asia/Shanghai`（内容的时区在管理页「发布设置」里，与此无关） |

> 上面这些变量也可以在**同一个目录**放一个 `.env` 文件写成 `DM_PORT=8080` 这样，效果一样；不写 `.env` 是完全可以的。

两个目录装什么：**数据目录**是 SQLite、录音、备份、导出和 `markdown/` 下的全部稿件；**配置目录**是 `runtime.json`、登录密钥环和管理页保存的凭据。它装着能签发登录 Cookie 的密钥，所以单独保存、不要混进普通内容备份。

## 2. 起服务

```bash
docker compose up -d       # 第一次会先拉镜像，通常一分钟内
```

看日志确认起来了，并记下管理员初始密码（如果上面填了 `Admin__InitialPassword`，这行会写「密码来自部署配置」，不会再显示密码）：

```bash
docker compose logs app | grep -A2 '已创建管理员账号'
```

看到 `healthy` 就算成功了：

```bash
curl http://127.0.0.1:18321/api/system/health
```

## 3. 手机装 APK

去 [Releases](https://github.com/Nero-UMU/DailyMusings/releases) 下载最新的 `DailyMusings-client-<版本>-android.apk`，传到手机上安装。APK 是自签名包（没上架应用商店），系统会提示「未知来源」，需要手动允许。同一页还给出 SHA-256，在意的话可以核对：

```bash
sha256sum DailyMusings-client-1.0.0-android.apk
```

## 4. 登录与配对

1. 浏览器打开 `http://<这台机器的IP>:18321/`，用 `admin` + 第 2 步拿到的初始密码登录。**首次登录会强制你同时改账号名和密码**。
2. 回「状态」页的「设备配对」区点「生成配对码」：一次性、十分钟有效。
3. 手机打开「每日随想」→ 设置页填 `http://<这台机器的IP>:18321` → 点「测试连接」→ 填配对码 → 点「配对」。
4. 之后就可以用「今日随想」页录音或手写，点「上传」把内容发到服务端。

**不知道这台机器的 IP？** 在服务器上执行：

```bash
hostname -I          # 或者：ip -4 addr show | grep inet
```

取那个 `192.168.x.x` / `10.x.x.x` / `100.x.x.x`（Tailscale）形式的地址。手机必须能直达这个地址：同一个局域网、连同一个 VPN，或者你把端口映射出去。**先在这台机器上 `curl http://127.0.0.1:18321/api/system/health` 自证可达**，再去怀疑手机那一侧。

要真正生成文章，还需要在管理页「模型管理」里填至少一个生成模型（默认 DeepSeek）的 API Key；转写与邮件同理，都在管理页里填，不需要重启用容器。

## 常用操作

```bash
docker compose logs -f app          # 跟踪日志
docker compose pull && docker compose up -d   # 升级到最新版
docker compose down                 # 停止（数据仍在这两份命名卷里）
docker compose down -v              # 停止并删掉命名卷（数据会一起没，谨慎）
```

**备份**：管理页「系统设置」里可以一键备份、导出可读包。用命名卷时，卷名是 `<项目名>_dm-data`（`docker volume ls` 里能看到），可以整卷拷出来：

```bash
docker run --rm -v <项目名>_dm-data:/from -v "$PWD":/to alpine tar czf /to/dm-backup.tgz -C /from .
```

用绑定挂载时直接备份那个宿主机目录即可。配置目录也应该单独留着——没有它，恢复后所有设备都要重新配对、管理员会话也会失效。

**从公网访问**：请在前面放一个终止 TLS 的反向代理（Caddy / Nginx / Traefik），不要直接把明文端口暴露到公网。明文 HTTP 可用但登录页会要求你主动确认风险——**确认不会让连接变安全**，密码、设备令牌、录音和文章都可能被同一网络中的他人截获。

## 出问题先看这里

| 现象 | 原因与处理 |
| --- | --- |
| `docker compose up -d` 报权限或写不进去 | 宿主机上执行 `docker compose logs app`；日志里若出现「无法纠正 … 的属主」，就在宿主机上 `sudo chown -R 1654:1654 <那个目录>`。Docker Desktop（Windows / macOS）上这种提示可以忽略 |
| 容器起来但浏览器连不上 | 端口映射与防火墙。`docker compose port app 18321` 看映射到哪儿了；云主机还要放行安全组 |
| 日志里没有初始密码 | 说明配置了 `Admin__InitialPassword`，或者管理员账号早就建好了（密码只打印一次）。忘了密码就删掉配置目录里的数据库卷重来，或用备份恢复 |
| 手机「测试连接」失败 | 手机与服务器要在同一个可达网络；地址必须是 `http://` 开头并带端口；服务器上 `curl http://127.0.0.1:18321/api/system/health` 先自证可达 |
| 模型调用报「没有密钥」 | 管理页「模型管理」里没填 API Key，或 Secret 文件权限不是 644（容器以 uid 1654 读取，600 的文件读不到） |
| Fedora / RHEL / CentOS 上挂载目录读不到 | SELinux：给绑定挂载加 `:z`，例如 `- /srv/dm/data:/var/lib/dailymusings:z` |
| 改了管理页的「监听端口」没用 | 这是有意的：容器部署下端口由部署文件独占（`DAILYMUSINGS_LOCK_LISTENING_PORT=1`），改 `ports` 左边那个数字再 `docker compose up -d` |

## 我要改代码 / 从源码构建

维护者通道只有一份服务定义，覆盖文件在 `deploy/`：

```bash
docker compose -f compose.yaml -f deploy/compose.yaml up -d --build
```
