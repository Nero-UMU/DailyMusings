客户端：修掉服务器不可达时今日页崩溃（真机验收发现）

阶段五的真机验收（Xiaomi 23127PN0CC / Android 16）跑 §17.3 第 1~2 步时发现：
把与服务器的通路切断后启动应用，进程当场崩溃（logcat -b crash 有完整调用栈）。

根因：今天页出现时的读取路径把 HttpRequestException 一路抛进了 async void OnAppearing。
「服务器连不上也能继续记录」正是 §9.2 的前提，而这条路径只存在于 MAUI 工程内部
（ICaptureApiClient 没有这个成员），所以既有测试根本碰不到它。

修法：
- 读取路径移进 Client.Core 并分类返回：InputListResult（Items / ServerReached / FailureCode），
  与上传路径共用同一套错误码；未送达、被拒绝、成功是可区分的三件事。
- 界面据此如实说明：「连不上服务器，暂时看不到服务器上的内容；本机待上传的内容仍在下面」，
  而不是把「连不上」显示成「今天还没有上传任何内容」；令牌失效单独提示去重新配对。
- 所有 async void 处理器加顶层兜底（GuardAsync / try-catch），任何异常变成一句提示而不是崩溃。
- 补 4 项测试覆盖读取路径的分类（不可达 / 未配对 / 401 / 非 JSON / 5xx）。

真机复核：同一台设备、同样切断通路后启动不再崩溃，界面显示上述提示；录两段语音
（4.1 秒 / 2.1 秒）并写一条文字后显示「3 条失败（连不上服务器）」且服务端条目数不变；
恢复通路点「立即同步」后「已上传 3 条」，服务端 5 条（4 语音 + 1 文字），
每条语音都转写成功并归入「晨跑」主题，磁盘 4 个真实 m4a（72,841 / 24,792 / 49,381 / 25,074 字节）。

产物：APK / MSIX / Windows 免安装包按修复后的代码重新构建并签名，校验值已更新
（docs/发布校验值.md）。全量测试 383 项通过（Client 34）。
